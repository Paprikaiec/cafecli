# Claude Code memory extraction and recall

Research date: 2026-10-17. Scope: the local `claude-code/` tree at commit `4b9d30f7953273e567a18eb819f4eddd45fcc877` (commit date 2026-03-31). Its [README](../../claude-code/README.md:1) describes an unofficial mirrored source snapshot. These findings describe the checked-out code, including gated branches; they do not establish current product rollout or remote feature flag values. No runtime experiment or network lookup was needed to answer this source analysis question.

## Answers

- **Extraction:** a background LLM agent can run at the end of an eligible main-agent query loop. Its prompt uses four memory types: `user`, `feedback`, `project`, and `reference`. This is model judgment guided by prose, rather than a deterministic four-score classifier. Running on every turn is conditional on feature flags, settings, throttling, and whether the foreground agent already wrote memory.
- **Injection:** ordinary `MEMORY.md` inclusion is context assembly. A separate gated retrieval path asynchronously selects and reads relevant memory files; the foreground query loop inserts the completed attachments. Extraction and recall are distinct jobs with different contexts.
- **Context:** extraction is a fresh fork of the current foreground conversation plus an extraction instruction, with isolated mutable tool state and a five-round limit. It is explicitly implemented as a subagent. Recall selection uses a small, stateless `sideQuery`, rather than the extraction subagent or a full conversation fork.

The implementation uses `async` functions, Promises, and the normal `query()` generator. The traced call path does not start a native thread, worker, or separate process for extraction/selection. “Background task” is the precise description at this layer. Sources: [stopHooks.ts](../../claude-code/src/query/stopHooks.ts:133), [extraction call](../../claude-code/src/services/extractMemories/extractMemories.ts:415), [fork query loop](../../claude-code/src/utils/forkedAgent.ts:543), [recall side query](../../claude-code/src/memdir/findRelevantMemories.ts:98).

## Extraction timing and gates

`query()` reaches `handleStopHooks()` in its no-follow-up branch, after producing a response without pending tool calls; API errors skip this path. The stop-hook context contains the messages used for the query plus the latest assistant messages. `handleStopHooks()` calls extraction with `void`, so it does not await the extraction before proceeding. This happens before later stop hooks can request continuation, so a hook-induced continuation can create another eligible stop attempt within what a user views as one turn. Sources: [query.ts no-follow-up branch](../../claude-code/src/query.ts:1062), [API-error check and stop call](../../claude-code/src/query.ts:1258), [context snapshot](../../claude-code/src/query/stopHooks.ts:84), [fire-and-forget call](../../claude-code/src/query/stopHooks.ts:141).

Conditions that prevent a literal “every turn” guarantee:

| Condition | Source |
| --- | --- |
| Build includes `EXTRACT_MEMORIES`; extraction initialization has run | [backgroundHousekeeping.ts:31](../../claude-code/src/utils/backgroundHousekeeping.ts:31), [stopHooks.ts:142](../../claude-code/src/query/stopHooks.ts:142) |
| Not bare mode; parent is the main agent, not a subagent | [stopHooks.ts:133](../../claude-code/src/query/stopHooks.ts:133) |
| `tengu_passport_quail` is enabled; fallback is `false` | [paths.ts:69](../../claude-code/src/memdir/paths.ts:69) |
| Noninteractive sessions additionally require `tengu_slate_thimble`; fallback is `false` | [paths.ts:73](../../claude-code/src/memdir/paths.ts:73) |
| Auto memory is enabled and remote mode is off | [extractMemories.ts:544](../../claude-code/src/services/extractMemories/extractMemories.ts:544) |

Auto memory itself defaults to enabled, but that does not imply background extraction defaults to enabled. The foreground system prompt always retains save instructions and can write memory directly, even without this background feature. The direct-write check detects Write/Edit tool-use requests to a memory path; it does not inspect a successful tool result before deciding to skip extraction. Sources: [auto-memory setting precedence](../../claude-code/src/memdir/paths.ts:21), [foreground/background relationship](../../claude-code/src/memdir/paths.ts:57), [direct-write detection](../../claude-code/src/services/extractMemories/extractMemories.ts:121).

## Four types and saving policy

| Type | What the prompt asks the model to retain |
| --- | --- |
| `user` | Relevant user role, preferences, responsibilities, expertise, and goals |
| `feedback` | Corrections and confirmations of non-obvious successful approaches, including why and when to apply the guidance |
| `project` | Goals, decisions, constraints, coordination, incidents, and deadlines not derivable from current code or git history |
| `reference` | Pointers to external information sources, such as a particular tracker project or dashboard |

The definitions and examples live in [memoryTypes.ts:113](../../claude-code/src/memdir/memoryTypes.ts:113). The extraction prompt imports those definitions and their “what not to save” section directly, making them prompt instructions rather than independent procedural classifiers. Exclusions include derivable architecture/file structure, git history, debugging recipes, existing CLAUDE.md contents, and ephemeral task state; even explicit user save requests are subject to those exclusions. Sources: [prompts.ts:84](../../claude-code/src/services/extractMemories/prompts.ts:84), [memoryTypes.ts:183](../../claude-code/src/memdir/memoryTypes.ts:183).

Before the fork, code scans existing memory headers and inserts a manifest so the model can update an existing topic file instead of creating duplicates. Normally it writes one Markdown file per memory, with `name`, `description`, and `type` frontmatter, and adds a pointer in `MEMORY.md`. When `tengu_moth_copse` is enabled, the prompt omits index maintenance because recall switches to file selection. Sources: [manifest scan and prompt construction](../../claude-code/src/services/extractMemories/extractMemories.ts:395), [save format and index instructions](../../claude-code/src/services/extractMemories/prompts.ts:55), [frontmatter example](../../claude-code/src/memdir/memoryTypes.ts:261).

## Extraction context and lifecycle

Each run uses the parent's exact system prompt, user/system context, tool definitions, model configuration, and current conversation prefix to share the API prompt cache. `runForkedAgent()` constructs `initialMessages = [...forkContextMessages, ...promptMessages]` and starts its own `query()` loop. Consequently, “last N messages” is an extraction instruction, not a physical slice of the API history: the model receives the entire currently retained parent prefix, which may already have been compacted. Source: [createCacheSafeParams](../../claude-code/src/utils/forkedAgent.ts:131), [fork setup and query](../../claude-code/src/utils/forkedAgent.ts:506), [last-N restriction](../../claude-code/src/services/extractMemories/prompts.ts:35).

`createSubagentContext()` gives the fork a distinct agent ID and query tracking chain, clones its file-read cache and content-replacement state, creates new trigger sets, links cancellation one way from parent to child, suppresses permission prompts, and disables most parent UI/state mutation callbacks. Parent options and some read access remain shared; it is selective state isolation rather than a deep clone of the whole application. Source: [createSubagentContext](../../claude-code/src/utils/forkedAgent.ts:345), [child cancellation](../../claude-code/src/utils/abortController.ts:68).

The tool list stays identical for prompt caching, but `canUseTool` restricts actual execution: Read/Grep/Glob, read-only Bash, and Write/Edit only inside auto memory. Other operations, including spawning Agent/MCP, are denied. REPL is admitted as a wrapper whose inner primitive calls are checked. The extraction caller sets `maxTurns: 5` and `skipTranscript: true`; the fork still has a subagent context ID, but skips the separate transcript recording ID and all sidechain transcript I/O. Sources: [permissions](../../claude-code/src/services/extractMemories/extractMemories.ts:171), [extraction parameters](../../claude-code/src/services/extractMemories/extractMemories.ts:415), [transcript handling](../../claude-code/src/utils/forkedAgent.ts:526).

Session state is a closure created at startup: last processed message UUID, eligible-turn counter, overlap guard, latest pending context, and outstanding Promises. If another eligible turn finishes while extraction runs, it keeps only the newest pending context and runs a trailing extraction afterward; this avoids simultaneous extractors. On success the cursor advances; on exceptions it remains so the messages can be reconsidered. If compaction removes the cursor UUID, message counting falls back to all retained user/assistant messages. Thus the extractor does not maintain an accumulating private conversation across runs; it repeatedly forks the current parent context and persists results in memory files. Sources: [closure state](../../claude-code/src/services/extractMemories/extractMemories.ts:296), [success cursor](../../claude-code/src/services/extractMemories/extractMemories.ts:429), [trailing extraction](../../claude-code/src/services/extractMemories/extractMemories.ts:503), [overlap handling](../../claude-code/src/services/extractMemories/extractMemories.ts:554), [compaction cursor fallback](../../claude-code/src/services/extractMemories/extractMemories.ts:82).

On completion the fork clears its cloned read cache and local initial-message array. Generated extraction messages are not appended to the main conversation; the caller may append a memory-saved notification. Noninteractive shutdown drains the in-flight extraction chain, with a default soft timeout of 60 seconds, after flushing the response. Sources: [fork cleanup](../../claude-code/src/utils/forkedAgent.ts:599), [notification](../../claude-code/src/services/extractMemories/extractMemories.ts:490), [drain](../../claude-code/src/services/extractMemories/extractMemories.ts:579).

## Injection and recall

There are two relevant paths:

1. **Ordinary index inclusion:** `getMemoryFiles()` reads the auto-memory entrypoint. Memoized `getUserContext()` renders it alongside instruction files into `claudeMd` context, which `prependUserContext()` places in request messages. This is awaited context assembly, without a selection subagent. Memory policy text is separately built into the system prompt by `loadMemoryPrompt()`. The extraction prompt's statement that the index is “always loaded into your system prompt” is therefore loose language: index content and system policy have different actual injection paths. Main-session compaction clears both the outer user-context cache and the inner memory-file cache. Sources: [entrypoint read](../../claude-code/src/utils/claudemd.ts:979), [user context](../../claude-code/src/context.ts:155), [request messages](../../claude-code/src/query.ts:660), [system memory policy](../../claude-code/src/constants/prompts.ts:495), [post-compaction cache reset](../../claude-code/src/services/compact/postCompactCleanup.ts:51).
2. **Gated relevant-memory prefetch:** with auto memory and `tengu_moth_copse` enabled, the index is excluded from normal context injection. Once per user turn, `query()` starts a cancellable Promise that selects and reads memory files while the main query proceeds. Sources: [index filter](../../claude-code/src/utils/claudemd.ts:1136), [once-per-turn start](../../claude-code/src/query.ts:297), [prefetch gates and lifecycle](../../claude-code/src/utils/attachments.ts:2361).

The recall selector receives the latest non-meta user text, a manifest of memory names/descriptions/types/timestamps, and recently successful tool names; previously surfaced files are filtered. It does not receive the full conversation or a fork of the parent's system prompt. It makes a Sonnet `sideQuery` with a dedicated selection prompt, a 256-output-token cap, and a JSON filenames result. This is a small LLM selection request, not a tool-running subagent. Sources: [input extraction](../../claude-code/src/utils/attachments.ts:2372), [selector](../../claude-code/src/memdir/findRelevantMemories.ts:77), [scan and manifest](../../claude-code/src/memdir/memoryScan.ts:21).

Scanning reads up to 30 frontmatter lines per candidate and retains the newest 200 memory headers. The code reads at most five selected memories, each up to 200 lines/4096 bytes, and stops starting new prefetches once prior surfaced content reaches 60 KiB. Single-word prompts are skipped. Sources: [scan limits](../../claude-code/src/memdir/memoryScan.ts:21), [selected files](../../claude-code/src/utils/attachments.ts:2231), [content limits](../../claude-code/src/utils/attachments.ts:269), [reading](../../claude-code/src/utils/attachments.ts:2279), [prefetch guards](../../claude-code/src/utils/attachments.ts:2377).

The foreground loop consumes only a settled prefetch after tools complete. It never blocks waiting for selection; an unfinished result gets another chance on the next tool iteration. A turn that ends before a consume opportunity may never inject the result. The loop creates `relevant_memories` attachments and places them into its own next-iteration messages; message serialization wraps them as meta user messages in `<system-reminder>`. The async selector does not mutate a live foreground model context. Sources: [consume](../../claude-code/src/query.ts:1592), [attachment return](../../claude-code/src/utils/attachments.ts:2236), [wire conversion](../../claude-code/src/utils/messages.ts:3708).

The prefetch controller follows parent cancellation and is aborted on query generator disposal. Paths and byte counts derive from surviving transcript attachments, so context compaction naturally permits later recall of memories whose attachments were removed. Sources: [prefetch dispose](../../claude-code/src/utils/attachments.ts:2388), [transcript-derived deduplication](../../claude-code/src/utils/attachments.ts:2244).

## Related mechanisms with similar names

`SessionMemory` is a separate session-summary mechanism with token-growth/tool-count triggers; defaults are initialization at 10,000 context tokens, updates after 5,000 growth, and three tool calls. It also uses a fork but writes its own session memory file, rather than performing the four-type durable-memory extraction described above. Sources: [thresholds](../../claude-code/src/services/SessionMemory/sessionMemoryUtils.ts:16), [session fork](../../claude-code/src/services/SessionMemory/sessionMemory.ts:302).

`autoDream` is a separate consolidation fork, gated by elapsed time, accumulated sessions, and a process lock. Its fallback thresholds are 24 hours and five sessions; it is not the per-turn extractor or recall selector. Source: [autoDream.ts](../../claude-code/src/services/autoDream/autoDream.ts:1).
