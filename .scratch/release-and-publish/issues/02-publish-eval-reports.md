# 02 — 评测报告公开化

Status: **ready-for-human**
Type: 技术写作 / 对外材料

## Parent

`.scratch/release-and-publish/PRD.md`

## 问题

`eval/swebench-live/` 下 5 份报告是这个项目最稀缺的资产，但目前只有 clone 仓库并翻到 `eval/` 子目录才看得到。README 主体完全没有指向它们的入口。

## 素材盘点（已有，不需新写实验）

| 报告 | 可讲的点 |
|---|---|
| `2026-06-08-cafecli-vs-claude-ab` | 与 Claude Code 同模型受控对照；差距 100% 归因 harness 而非模型；产出 4 项修复项 |
| `2026-06-26-phase0-editfile-rebaseline` | **写代码前先用零代码旋钮再基线**；用数据 defer 掉了原计划的 compile-gate |
| `2026-07-14-hooks-ab-builtin-tenants` | 诚实的近似零结果；主动勘误；反作弊红线；证据不支持翻默认 |
| `2026-07-20-repeated-safe-edit-ab` | 过程指标 p=0.0078 显著、主指标 p=1.0 不显著，**两个都报** |
| `README` + ADR 0013 | 抗污染窗口、双层数据质检、失败归因六分类、干净池枯竭的诚实记录 |

## 要做的

一篇面向外部读者的长文（中英皆可），主线建议按**叙事链**而非按报告顺序：

> 为什么换数据集（训练污染）→ 怎么保证 A/B 公平（含主动发现并修正自己引入的 prompt 不对称）→ 打平时如何还能比出高下（过程轴归因）→ 发现差距后怎么逐条修 → 修完之后哪些验证有效、哪些是零结果

同时在 README 加一个「评测」章节作为入口，指向 `eval/swebench-live/`。

## 不要删的东西

近似零结果、2026-07-21 的勘误、「N=20 不可达 / 干净池接近枯竭」的记录、safe-edit 主指标不显著——**这些是可信度的来源，不是瑕疵**。公开版本若把它们修饰掉，这篇文章就和满地的项目宣传贴没有区别了。

## 验收

外部读者不 clone 仓库就能读懂：做了什么实验、结论是什么、哪些结论是负面或零结果。

## 成本

约半天，纯整理，素材全部现成。
