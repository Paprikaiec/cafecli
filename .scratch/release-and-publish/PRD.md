# 对外发布与传播（release-and-publish）

Status: **ready-for-human**
Type: 对外材料（纯本地整理，无机时依赖）

## 为什么

项目刚上线，**零 star、零 issue**。求职材料里它是最强的单点证据，但外部读者验证它的成本目前过高：

1. **只能编译，不能安装。** 现状要 `git clone` + `mvn clean package` 才拿得到可运行的东西。对随手点进来的人，「可安装」和「可编译」是两个门槛量级。
2. **最稀缺的资产埋在仓库里。** `eval/swebench-live/reports/` 那 5 份报告——抗污染窗口选择、双层数据质检、失败归因六分类、诚实的近似零结果、主动勘误——**质量高于代码本身**，而且是同类项目几乎不会有的东西。它们现在只有 clone 下来翻目录才看得到。

## 关键判断

**报告能被转发，代码不能。** 这是零 star 状态下最快的传播路径：一篇讲「我把自研 agent 和 Claude Code 做受控对照，然后诚实报告自己输在哪」的文章，比任何 README 优化都更可能被读完并转出去。

## 不做什么

不为涨 star 去发无实质内容的宣传贴，不把「近似零结果」和「主动勘误」这些诚实记录从公开版本里删掉——它们正是可信度的来源。
