# 浏览层默认折叠思考，Ctrl+T 层内一键揭示（修订 ADR 0012）

ADR 0012 定「[[转写浏览层]] = 强制展开所有块」+「Ctrl+T 键位退役，折叠唯一入口是 Ctrl+O」。实测暴露：思考推理又长又低信噪，进浏览层复盘一轮时推理铺满整屏，把真正想看的工具 / 代码 / diff 挤到看不见。浏览层的本意是「看全一轮」，但用户复盘时问的通常是「它做了什么」，只偶尔想追「它为什么这么做」。

## 决策

**浏览层默认折叠思考，其余全展开；Ctrl+T 在层内一键揭示思考。**

- **默认展开**[[保留窗口]]的工具 / 代码 / diff / 答案块；**思考只留折叠头**（`思考 N 行`）。浏览层是「它做了什么」的视图。
- **Ctrl+T 只在浏览层内生效**：一键展开 / 收起**全部**思考块（「它为什么这么做」）。这不是重开 ADR 0012 退役的全局 Ctrl+T 入口——进入浏览层仍**只由 Ctrl+O**，层外无 Ctrl+T 绑定。
- **无状态**：Ctrl+T 态只存活于本次浏览，`ESC`/`q`/`Ctrl+O` 退出后复位；下次 Ctrl+O 重开又是折叠态。
- **保持纯行滚动视口**：不引入按块光标，Ctrl+T 是全局开关而非「展开光标所在块」。默认流不受影响（默认流本就折叠思考）。

## 被否决的方案

- **按块光标 + Ctrl+T 展开选中块**：等于把 ADR 0011 的按块光标模型重新装回来——0012 刚为了纯行滚动的简洁把它删掉，不回头。
- **浏览层完全不收录思考**：省了一次 Ctrl+T，但「为什么这么做」彻底不可追溯，牺牲过大。
- **跨 Ctrl+O 记住 Ctrl+T 态**：要给会话多背一份浏览层状态，收益仅是重开免按一次 Ctrl+T，不值。取无状态。

## 后果

- 修订 ADR 0012：浏览层不再是「强制展开所有块」，而是「展开工具 / 代码 / diff / 答案，思考默认折叠」；「Ctrl+T 已退役」修订为「Ctrl+T 仅作浏览层内的思考开关，非全局入口」。`CONTEXT.md`「终端渲染」段 [[转写浏览层]] / [[折叠块]] 已同步。
- 浏览层帮助行加入 `Ctrl+T thinking`。
- 本轮同批的默认流视觉修正记于同一 fixup wave（各自不单独立 ADR）：退役[[块色条]]竖条（思考 / 工具 / 代码 / diff 折叠头改纯文本，类型靠标签文案分辨）、diff 改 Claude-Code「Update」式行号槽 + 红 / 绿背景（退役 `@@` 头，见 [[折叠块]]）、统一「块间恰一个空行」的单一归属（条带拥有条目间空行，块与 markdown 不在各自边缘补空行）。
- `TranscriptOverlayModel` 新增思考折叠开关态与 `Ctrl+T`→Action 解码；仍是纯 reducer，行滚动视口不变。
